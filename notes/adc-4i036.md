# PBX Web Log Parsing - Deployment Issues Analysis

## Task Completion Summary

Successfully parsed and filtered pbx-web logs to extract deployment-relevant events.

## Data Sources Processed

1. **VictoriaLogs**: `logs/pbx-web-victorialogs-raw.jsonl` (78MB, nginx access logs)
2. **Container Logs**: Current pod logs from pbx-web namespace
3. **Pod Events**: Kubernetes events and deployment history

## Results

### Total Events Found: 1,438

#### HTTP 5xx Server Errors: 1,420
- HTTP 500: 371 errors (Internal Server Error)
- HTTP 502: 347 errors (Bad Gateway)
- HTTP 503: 349 errors (Service Unavailable)
- HTTP 504: 353 errors (Gateway Timeout)

#### Connection Errors: 18
- Connection reset by peer: 12 errors
- Broken pipe: 6 errors

#### Pod Events: 0
- No OOMKilled events detected
- No CrashLoopBackOff events detected
- All pods showing 0 restart counts (healthy state)

### Key Findings

1. **HTTP Error Distribution**: Evenly distributed across all 5xx error types (500-504)
2. **Connection Issues**: Periodic connection reset and broken pipe errors (intermittent)
3. **Pod Health**: All pods stable with no restart events in the analyzed period
4. **Error Context**: Most 5xx errors appear correlated with recording fetch failures

## Output Files Generated

1. **`logs/pbx-web-parsed.jsonl`** (1,438 lines)
   - Structured JSONL with deployment-relevant events
   - Fields: source, error_type, severity, message, timestamp

2. **`logs/pbx-web-summary.json`** (25 lines)
   - Aggregated statistics by error type
   - Summary counts and distributions

3. **`scripts/parse_pbx_web_logs.py`** (337 lines)
   - Reusable parsing script for future log analysis
   - Supports multiple data sources (VictoriaLogs, container logs, events)
   - Pattern matching for HTTP errors, connection issues, pod events

## Error Patterns Detected

The parsing script identifies these deployment-relevant patterns:
- HTTP 5xx status codes (500, 502, 503, 504)
- Connection errors (errno 104, errno 32)
- Pod restart indicators (OOMKilled, CrashLoopBackOff)
- Timeout indicators
- Recording fetch failures

## Reusability

The parsing script can be run again to:
- Process new log data as it becomes available
- Monitor deployment issues over time
- Filter different time periods or log sources
- Generate trend analysis of error patterns

Usage:
```bash
.venv/bin/python scripts/parse_pbx_web_logs.py
```

## Data Quality Notes

- VictoriaLogs retention is limited (<7 hours available)
- Container logs cover current pods only (~8-22 days depending on pod age)
- Historical pod restart events not accessible in available log sources
- Parse results represent visible deployment issues in available data window
